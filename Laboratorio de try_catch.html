Anatomía de un try/catch

try { // código que se puede romper } catch (TipoDeError e) { // qué hacer si se rompe } // el programa sigue acá

Si una línea del try lanza un error, las líneas siguientes del try no se ejecutan: se salta directo al catch. Si no hay error, el catch se ignora.

InputMismatchException
teclado.nextInt() recibe algo que no es un número entero. Necesita import java.util.InputMismatchException;
ArithmeticException
División entera entre 0: 10 / 0.
ArrayIndexOutOfBoundsException
Posición que no existe en el array: v[5] cuando v.length es 5.
NumberFormatException
Integer.parseInt("hola"): el texto no se puede convertir a número.
teclado.next()
Dentro del catch de un nextInt(), descarta lo que se escribió mal. Sin esta línea, un bucle que vuelve a pedir el dato nunca termina.

En los ejemplos se omiten la clase Main, el main y los import para abreviar. teclado es un Scanner ya creado.
